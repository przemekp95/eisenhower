# TASK-028 Client Image Privacy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ensure web and mobile OCR uploads contain no EXIF, XMP, IPTC, JPEG comment, or PNG text metadata while preserving review-first behavior.

**Architecture:** Keep byte sanitization as a pure API-client utility with literal binary fixtures. At the mobile boundary, re-encode any picker-supported image to JPEG with Expo ImageManipulator, remove metadata segments from the generated bytes, upload only the sanitized cache file, and delete it in `finally`. At the web boundary, sanitize supported JPEG/PNG bytes into a new `File`, pass plain text unchanged, and fail closed for unsupported image encodings.

**Tech Stack:** JavaScript, Node test runner, Jest 29, Expo SDK 57, `expo-image-manipulator`, `expo-file-system`.

## Global Constraints

- Do not alter the original picker asset used by the review preview.
- Do not upload the original file when sanitization fails.
- Remove JPEG APP1, APP13, and COM segments before the Start of Scan marker.
- Preserve pixel scan data and non-private structural segments byte-for-byte after ImageManipulator re-encoding.
- Delete the generated cache file after both successful and failed uploads.
- Keep physical Android/iOS acceptance open.
